# Aloud — Sub-project Instructions

Local screen-and-selection reader. One hotkey drags a rectangle and hears the text inside it read aloud; another reads the current selection. Fully local — no cloud, no account, no network. macOS first, Windows second, one codebase.

**DB project row:** `P-90212`. Status, phase and milestones live there and on the dashboard — **never in this file**.

Personal tool for Andrii's two machines. Built to product standards so that selling it later is a distribution problem, not a rewrite.

## Hard constraints

1. **Zero runtime system dependencies.** Everything bundled or statically linked. No "first install espeak-ng" step, ever. This is the line between a product and a README of setup chores — it is why Natural-Voice-TTS is not shippable.
2. **No voice cloning. Permanently.** OpenRAIL-M Attachment A (g) bars non-consensual impersonation. Do not add it, do not prototype it.
3. **Licence obligations are load-bearing before any release.** Supertonic is MIT *code* + OpenRAIL-M *weights* — do not conflate them. Shipping the weights requires: Attachment A mirrored into the EULA as an enforceable provision, a copy of the licence shipped, attribution retained. Commercial use is permitted and royalty-free; the obligations are paperwork. Rektor drafts the EULA clause before money changes hands.
4. **The region overlay is one window per monitor**, each carrying its own scale factor, with coordinates normalised into a global virtual-desktop space. Never a single fullscreen window. This is [pot-app#1161](https://github.com/pot-app/pot-desktop/issues/1161) — an open bug on a 19.2k-star app — and it is cheap to design in and expensive to retrofit.
5. **First audio must arrive far sooner than whole-passage synthesis, and it is tested.** The Chunker exists solely for this. The guard is a **ratio** (`tests/latency_budget.rs`): time from `Player::speak` to the first buffer reaching the sink must be ≤ 70% of one-shot whole-paragraph synthesis, plus an append-count check. Do not "simplify" the chunker away, and do not replace the ratio with an absolute millisecond budget — an absolute number asserts a property of the *machine*, not the code, and fails on any busy laptop. Measured 2026-08-08: **synthesis speed is wholly load-dependent** — the same sentence takes ~7s at load 4 and ~15s at load 24 on this M1 Air, in both the Rust build and the Python reference. The "~1.5s to first word" figure in the design spec holds only on a genuinely idle machine. An absolute 2.0s check exists but is `#[ignore]`d for that reason.
6. **Never pass a user-facing speed to the TTS engine.** Supertonic's `speed` argument is not a playback control: it divides the duration predictor's output and that shortened number sizes the latent the decoder renders into, so above ~1.1× the decoder silently elides phonemes and then whole words — no error, nothing in the log. Andrii lost `on screen; Aloud` from mid-sentence this way at his configured 1.5× (2026-08-10). `src/tts/supertonic_engine.rs` therefore always calls the engine at `ENGINE_SPEED = 1.0`, and speed is applied to the rendered audio by `src/tts/timestretch.rs` (SOLA, pitch-preserving). Do not plumb `speed` through to `TextToSpeech::call`, and do not "simplify" the time-stretch into a resample — a resample raises a male voice seven semitones at 1.5×. The pin itself is guarded **in the default `cargo test --release` run — locally, and only locally** by `tests/engine_speed_pin.rs`. **GitHub Actions does not run it** (it needs the model, which no runner can obtain), so a green tick on a PR says nothing about this constraint or about constraint 5; run the full suite by hand before trusting a change to `src/tts/`. The test needs no transcriber: it asserts that synthesising at speed S returns exactly what synthesising at 1.0 and time-stretching by S returns, which is only true while the engine is driven at 1.0 (verified to fail by 1642 samples against a 64-sample tolerance when `job.speed` is re-plumbed into `TextToSpeech::call`). The retiming itself is covered by the unit tests in `src/tts/timestretch.rs`. End-to-end content is covered by `tests/speed_preserves_words.rs`, which is ASR-backed and **`#[ignore]`d** — run it whenever you touch `src/tts/`: `cargo test --release --test speed_preserves_words -- --ignored`. Full evidence in [`docs/2026-08-10-text-drop-diagnosis.md`](docs/2026-08-10-text-drop-diagnosis.md). **The pin applies below 1.0 as a uniformity choice, not an evidenced one:** every measurement behind this constraint is at 1.0 or above, and below 1.0 the mechanism is provably benign — `duration /= 0.7` gives the decoder *more* canvas than it asked for, so word-drop cannot occur there. One code path is worth more than a speed-dependent branch, and 0.7-1.0 is the least-used part of the slider, but nobody has A/B-listened engine-native vs stretched at 0.7× on M5. Do that before treating sub-1.0 stretching as verified.
7. **The Windows half cannot be built or tested on the Mac.** WinRT bindings do not compile on macOS. `cfg`-gate per platform; finish macOS fully first; build on the PC via a `BKM/PC-Queue/` brief.
8. **Everything platform- or engine-specific lives behind a seam** (`RegionSelector`, `OcrEngine`, `SelectionGrabber`, `TtsEngine`). If a platform `#[cfg]` is leaking into pipeline logic, the seam is in the wrong place.
9. **Check `df -h /` before installing toolchains or models, and again after any build.** The M1 Air is small and has run critically low before — it hit 2.3 GB free during the M3 Tauri build.
10. **Build and test in `--release`, not debug.** `target/debug` costs ~3 GB on top of release's ~2.2 GB and offers nothing here: ONNX inference in a debug build is several times slower, so the timing-sensitive tests are misleading there anyway. A stray `cargo test` (which defaults to debug) recreates the whole 3 GB tree. If you find `target/debug` present and disk is tight, deleting it is safe.
11. **A new file under `dist/` needs a clean rebuild to actually take effect.** `dist/` is embedded at compile time by `tauri::generate_context!()`, but `cargo` does not watch it for `rerun-if-changed`, and `generate_context!()` cannot track a file that didn't exist at the previous compile. Adding a new file under `dist/` and rebuilding normally therefore silently embeds a **stale** binary — no error, no warning. If you touch `dist/`, run `cargo clean -p aloud --release` before the next build. This cost real time during M4.
12. **Launch-at-login state lives in the OS, not in `settings.json` — and Aloud never re-registers to "correct" it.** The real state is macOS's Background Task Management store, read via `SMAppService.mainApp.status`; the persisted `launch_at_login` bool is only a record of what the user asked for. The user can switch Aloud off in System Settings → General → Login Items and **Aloud is never notified** — that surfaces as `RequiresApproval`, and re-`register()`ing on it would silently override a deliberate opt-out. So: the settings toggle renders the live status (on **only** for `Enabled`), `set_launch_at_login` returns the OS's read-back status rather than the request, and startup reads-and-reports without ever writing. A toggle that reports intent instead of reality is the exact defect class this app has spent a week removing. Spike evidence and the full design: [`docs/2026-08-10-launch-at-login.md`](docs/2026-08-10-launch-at-login.md).

13. **A paused sink is not a stalled device, and pause is not stop-and-resynthesise.** Pause is real: `rodio`'s `pause()` acts on the output side via `Pausable`, which yields silence *without advancing the inner source*, so queued buffers survive untouched and resume continues at the exact sample (verified against a real device by the `#[ignore]`d `rodio_really_pauses_without_discarding_buffers` in `tests/player_pause.rs` — run it if you touch `src/play/`). Two invariants hold it up and both are load-bearing. **(a)** A paused sink's `queued()` depth is frozen *by definition*, so `Player::wait_for_drain`'s 30s stall watchdog must not count time spent paused — that is `StallWatch::observe`'s `paused` branch. Do not "simplify" it away, and do not fix a paused-read abort by *raising* `STALL_TIMEOUT`: that weakens the guard against a genuinely dead device and still breaks on a longer pause. **(b)** `AudioSink::stop()` must clear the paused state, and `Player::pause()` must refuse **until audio has actually reached the sink** — otherwise a paused-and-empty sink silently swallows the *next* read, with a queue depth that never moves. `is_speaking()` alone is not that predicate and never was: `Player::speak` sets it *before* the first `engine.synthesize()` call, so it is true through the whole seconds-long silent pre-roll, and true again in the gap between a `stop()` and the speaking thread unwinding — both of which are the empty-sink case. `Player` therefore also tracks `audible` (set at the first `append`, cleared by `speak` entry and by every stop path) and `pause()` requires both. Do not "simplify" it to `sink.queued() > 0`: synthesis runs *behind* playback on a loaded machine, so an honest mid-read moment can show a depth of zero and that would refuse real pauses. **(c) A third rodio contract, found 2026-08-10:** `rodio::Player::append` *begins* with an unbounded `sleep_until_end()` when a stop is outstanding and buffers are still counted (`stop()` only sets a flag; the queue is emptied on the audio output thread). On a device that has stopped consuming it never returns — and since the thread never reaches `wait_for_drain`, the 30s stall watchdog never runs either, so the busy flag is held forever and the app is silently bricked. `RodioInner` marks the stop and waits, bounded, for `len()` to hit zero before appending. Full write-up: [`docs/2026-08-10-pause-resume-phase1.md`](docs/2026-08-10-pause-resume-phase1.md).
14. **⌘⇧A is decided from the delivered text, and only ⌘⇧A.** The selection path is a macOS Service, so every invocation hands Aloud the selected text — which is what makes "the same passage again" and "this other passage instead" distinguishable, with no mode and no second chord. The decision is a pure function, `intent::decide_selection` (`src/app/intent.rs`): same text → toggle pause on the read in flight; different text, or a region read in flight → stop it and read the new selection; nothing in flight → read it. **Keep it pure** — inlined into `App` it would be reachable only through a live `Player` and an audio device, i.e. testable by ear, which is precisely what the seam bought. Five things around it are load-bearing and are each pinned by a test in `tests/selection_toggle.rs`. **(a)** The comparison key is `text.trim()` — ends only, interior untouched, and on the *delivered* text rather than the normalized text that reaches the engine. Do not make it raw (an invisible trailing newline from a sloppy re-selection would restart the passage instead of pausing it) and do not collapse interior whitespace (two selections the user can see are different would compare equal). **(b)** The Interrupt path must `stop()` **and then wait** for the busy flag: `Player::stop` is asynchronous, so a try-acquire loses the race and drops the new selection having already silenced the old one. The wait is bounded (`TAKEOVER_WAIT`, past the 30s stall watchdog) purely as a hang-guard, and it is single-slot (`taking_over`) so two fast presses cannot queue up and read the same text twice. The stop is **re-asserted on every poll**, not issued once: `Player::speak` clears the stop flag as its first act, and the read being displaced may hold the busy flag without having entered `speak` yet, so a single stop can be wiped and the displaced passage then plays out in full. **(c)** Nothing may be stopped before the new text is known to be speakable — `normalize_ocr` empties a multi-block all-digit selection that `selection_worth_speaking` accepts, so `App::speak_selection` runs `actions::speakable_selection` **first** and returns `SelectionOutcome::Empty` without touching the read in flight. **(d)** `App::stop()` clears `current` itself; a stopped read goes on holding the busy flag (and `current`) for up to one `engine.synthesize()` call, and a stale `current` there makes a Stop-then-⌘⇧A press a pause of silence. **(e)** The **region** path (⌘⇧R) stays a silent no-op on a repeat press — it carries no text, so a deliberate re-trigger and a stray double-press are indistinguishable there, and the stop-then-start rationale rejected in `src/app/mod.rs` still holds in full. Full write-up: [`docs/2026-08-10-selection-toggle.md`](docs/2026-08-10-selection-toggle.md).

15. **Every registered chord is an ordinary chord, never a media key — and pause gets no chord of its own.** Two halves, both load-bearing. **(a) No media key, ever.** Media keys are the only path in `global-hotkey` that reaches `CGEventTapCreate`, and an active tap from an untrusted process is refused outright (measured, macOS 26.6 — `docs/media-key-control-research.md` §4). So a media key survives neither a load nor a save (`Settings::normalize`) nor the trip to `register()` (`apply_shortcut_with`, via `src/shortcut.rs::is_media_accelerator`). This now governs `region_shortcut`, the only persisted shortcut — do not weaken the screen just because there is one field again, and do not re-add a second field without putting it through the same screen. **And the sanctioned alternative has been tried and rejected, so this is not a gap waiting to be filled.** `MPRemoteCommandCenter` was the one route to the media key that needs no tap and no TCC grant; it was built as Phase 2 (F8 → `toggle_pause`, `objc2-media-player`, next/previous/seek disabled) and **dropped on the owner's hands-on gate test, 2026-08-10: when a read ended, control never went back to Music.app.** That hand-back was the single gate the research named as decisive, and it is the failure mode that makes the feature worse than not having it — the owner's music controls stay broken after every read. The work is preserved, unmerged, at tag `experiment/media-key-mpremote` (parent `00d044f`); the branch's own report is `docs/2026-08-10-media-key-phase2.md` **on that tag only**, and its programmatic finding that hand-back worked is exactly what pressing the key disproved. Do not re-propose the media key from the research doc's recommendation without reading that outcome first. **(b) Pause has no hotkey, deliberately.** Phase 1 shipped `Cmd+Shift+P` / `pause_shortcut`; it was removed once `⌘⇧A` became a selection-aware play/pause toggle (constraint 14), because a second chord was then redundant surface and `⌘⇧P` is VS Code's Command Palette, which a non-exclusive global hotkey wins while Aloud runs. Pause is reached by `⌘⇧A` and by the tray's Pause/Resume item — and **the tray item is not a convenience**: macOS will not invoke a Service with nothing selected, so it is the only pause control that works without a live selection. Do not delete it, and do not label it with a chord (naming `⌘⇧A` there would be a lie in exactly the case the item exists for). The audio-layer machinery is untouched by all of this and stays — see constraint 13. If pause ever needs a chord again, note what its removal restored: the global-shortcut handler registers exactly one chord, so the probe-ordering trap in `docs/2026-08-10-pause-resume-phase1.md` §4 comes back the moment a second one is added. A `settings.json` written by a Phase 1 build still carries the retired `pause_shortcut` key; it must keep loading cleanly and must not reset anything else — `Settings` therefore carries no `deny_unknown_fields`, pinned by `a_settings_file_still_carrying_the_retired_pause_shortcut_loads_untouched`.
16. **The selection Service handler hands activation straight back, and that call is load-bearing.** macOS activates the Services provider as part of delivering the message — `NSApp.isActive` is already `true` on the first line of `readSelection:userData:error:`, so activation cannot be declined, only relinquished. `read_selection` therefore calls `NSApp.hide(nil)` first, before the pasteboard read and before every early return. Do not "simplify" it away, do not move it after the early returns, and do not swap it for `NSApp.deactivate()` — deactivate was measured inert here, inline and re-scheduled at 50/200/500/1000 ms. The hide is unconditional on purpose, settings window open or not. Evidence, the probe harness, and the by-hand pass condition (0 frontmost changes): [`docs/2026-08-10-selection-focus-steal.md`](docs/2026-08-10-selection-focus-steal.md).

## Stack

- **Tauri 2** (menubar shell, global-shortcut plugin, tray), Rust core, web UI. Packaging on macOS is **hand-assembled**, not the Tauri CLI bundler: `cargo install tauri-cli` drove this M1 Air to 2.0 GB free, so `packaging/make-app.sh` builds `target/Aloud.app` directly (see `README.md`). Do not reach for `cargo tauri build` here. Windows packaging (M6) is undecided — revisit then, it does not inherit this constraint.
- **Settings window (`dist/`):** hand-written HTML/CSS/JS, no bundler, no `package.json`, no build step — edit the files directly and rebuild the Rust binary (see Hard constraint 11, the `dist/` clean-rebuild trap).
- **Do not add `tauri-plugin-autostart` on macOS.** Read from its source (M4 research): on macOS it offers only LaunchAgent and AppleScript modes, and its default LaunchAgent mode writes `ProgramArguments` pointing at `Contents/MacOS/aloud` — the inner binary — which bypasses LaunchServices, the mechanism that registers the `NSServices` provider. Adopting it as-is would silently kill "Read Aloud". Launch-at-login is built instead on **`SMAppService`** via `objc2-service-management` (`src/login_item/`) — see hard constraint 12 and [`docs/2026-08-10-launch-at-login.md`](docs/2026-08-10-launch-at-login.md). **The ban is macOS-scoped, and deliberately so:** on Windows the same plugin uses the HKCU `Run` key, a different mechanism with none of this failure mode, and [`docs/M6-platform-research-windows.md`](docs/M6-platform-research-windows.md) §2 recommends it there. If M6 adopts it, `cfg`-gate the dependency to Windows so it cannot reach the macOS build.
- **TTS:** Supertonic 3 via its first-party Rust SDK over ONNX Runtime. Defaults **F5** (female) and **M5** (male). 31 languages; `lingua-rs` picks the tag. Kokoro stays wired as the licence-clean fallback.
- **OCR:** bundled Swift helper → Vision (macOS); `Windows.Media.Ocr` via the `windows` crate (Windows). Never Tesseract.
- **Model:** 385 MB, downloaded on first run, not shipped in the installer. All ten voice styles together are under 3 MB — ship them all.
- **Audio:** `cpal` / `rodio`.

## Conventions

`python3 memory/memory.py project --action link --project-id 90212 --link-id <N>`

Naming is not settled — "Aloud" is a working name and a product-step decision.
